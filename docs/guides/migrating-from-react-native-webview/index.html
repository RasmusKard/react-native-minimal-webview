Migrating from react-native-webview¶

This page maps each react-native-webview prop to its counterpart here, and lists the defaults and behavior that differ and recipes for what has no prop. The requirements are in the README.

Most props are platform settings by the same name: bounces is ios={{ scrollView: { bounces: false } }}, and textZoom is android={{ settings: { textZoom: 120 } }}. Android keys are setter names without set, so setBuiltInZoomControls is android.settings.builtInZoomControls.

The keys autocomplete, and an enum string becomes a constant: cacheMode: 'LOAD_NO_CACHE' is AndroidConstants.WebSettings.LOAD_NO_CACHE (platform settings).

Defaults that differ¶

react-native-webview Here For react-native-webview's
Android overscroll Always The platform's android.webView.overScrollMode: 0
iOS inline video Off On ios.configuration.allowsInlineMediaPlayback: false
iOS AirPlay Off On ios.configuration.allowsAirPlayForMediaPlayback: false
iOS content insets never, indicators not adjusted automatic, indicators adjusted Two ios.scrollView keys, below
iOS debugging (webviewDebuggingEnabled) Off On in __DEV__ ios.webView.inspectable: false

The same settings in one object, debugging left on:

import { IOSConstants, WebView, type WebViewProps } from 'react-native-minimal-webview';

export const rnwDefaults = {
  ios: {
    configuration: { allowsInlineMediaPlayback: false, allowsAirPlayForMediaPlayback: false },
    scrollView: {
      contentInsetAdjustmentBehavior: IOSConstants.ContentInsetAdjustmentBehavior.never,
      automaticallyAdjustsScrollIndicatorInsets: false,
    },
  },
  android: {
    webView: { overScrollMode: 0 }, // 0: View.OVER_SCROLL_ALWAYS
  },
} satisfies Pick<WebViewProps, 'ios' | 'android'>;

export function Browser() {
  return (
    <WebView
      source={{ uri: 'https://example.com' }}
      ios={rnwDefaults.ios}
      android={rnwDefaults.android}
      style={{ flex: 1 }}
    />
  );
}

To add your own keys, merge each root: ios={{ ...rnwDefaults.ios, scrollView: { ...rnwDefaults.ios.scrollView, bounces: false } }}.

Behavior that differs¶

react-native-webview Here For react-native-webview's
Android fullscreen video (allowsFullscreenVideo) Off On (onFullscreenChange) A native hook that takes onShowCustomView
iOS universal links Open the app that claims them Load in place An external rule for the host
Downloads Android: saved to Downloads Open externally, or onDownload saves them downloadManager (Android)
Renderer crash Reported The core reloads (onProcessGone) Keep reload() only for recovered: false
Messaging Every page; on Android every frame allowedOrigins, main frame An iframe's: a native hook
Injected script Document end, every origin Document start, its origins addEventListener('DOMContentLoaded', …); origins: ['*']
Failed load An error view over the page iOS keeps the old page, Android shows its own The error screen
Android file input Offers the camera when the app has its permission The system chooser, which ignores capture onFileRequest
Android camera and microphone, and location with geolocationEnabled Granted to every page, after asking the OS Denied onPermissionRequest

Props with no counterpart¶

react-native-webview Why
autoManageStatusBarEnabled iOS shows WebKit's own fullscreen
useSharedProcessPool WKProcessPool has had no effect since iOS 15
ignoreSilentHardwareSwitch react-native-webview keeps a silent <audio> playing in the page for it
enableApplePay Apple Pay works with injected scripts since iOS 16
lackPermissionToDownloadMessage onDownload saves into the app's cache, and downloadManager into Downloads: neither needs a permission

What else changes¶

onNavigationStateChange keeps its name, but fires on every state change, progress and title included. onLoadStart and onLoadEnd keep theirs too, and get the NavigationState instead of a native event. userAgent is the same prop.

Remove the LSApplicationQueriesSchemes (iOS) and <queries> (Android) entries you added for the schemes a page opens (onOpenExternal).

onShouldStartLoadWithRequest¶

Navigation rules replace the callback, and the first rule that matches decides.

import { WebView } from 'react-native-minimal-webview';

// Stands in for what your onShouldStartLoadWithRequest callback decided
const isTrusted = (url: string) => url.startsWith('https://example.com/');

export function Browser() {
  return (
    <WebView
      source={{ uri: 'https://example.com' }}
      navigationRules={[
        { host: ['example.com'], action: 'allow' },
        { scheme: ['http', 'https'], mainFrame: false, action: 'allow' }, // iframes
        { mainFrame: true, action: 'ask' }, // the rest: onNavigationRequest answers
      ]}
      onNavigationRequest={({ url }) => (isTrusted(url) ? 'allow' : 'block')}
      style={{ flex: 1 }}
    />
  );
}

Your rules replace the defaults, defaultNavigationRules: spread it after yours to keep them.

A rule decides natively, so a busy JS thread doesn't hold a navigation up. react-native-webview's Android blocks the UI thread while it waits for the callback, and lets the navigation through when the callback is late. Its iOS waits for the answer.

The request has mainFrame in place of isTopFrame, and userInitiated in place of navigationType: 'click'. It has no mainDocumentURL. A new window (onOpenWindow) is a request with newWindow: true.

react-native-webview's iOS also asks about the source load, reloads, back/forward and form POSTs. The rules skip them (navigationRules).

After the rules block a server redirect, the state is the page before it, with outcome cancelled. react-native-webview reports the redirecting URL as still loading (iOS), or the blocked URL as loaded (Android).

injectJavaScript¶

evaluate takes an expression, not statements, and resolves with its value (evaluate).

Wrap the statements you passed injectJavaScript in a function you call, without the trailing true;, as in the scripts example.

postMessage and onMessage¶

The bridge replaces both, with calls that return promises, and events, in both directions. It serves only the origins you allow.

Pages that use window.ReactNativeWebView.postMessage and message events keep working with reactNativeWebViewMessages in injectedScripts. Its example shows what replaces onMessage and postMessage.

Loading and error screens¶

Draw the loading and error views yourself, over the WebView, from the navigation state and onError:

import { useRef, useState } from 'react';
import { ActivityIndicator, Button, StyleSheet, Text, View } from 'react-native';
import {
  WebView,
  useWebViewState,
  type LoadErrorEvent,
  type WebViewRef,
} from 'react-native-minimal-webview';

export function Browser() {
  const ref = useRef<WebViewRef>(null);
  const { loading } = useWebViewState(ref);
  const [error, setError] = useState<LoadErrorEvent | null>(null);

  return (
    <View style={{ flex: 1 }}>
      <WebView
        ref={ref}
        source={{ uri: 'https://example.com' }}
        onError={(e) => e.kind !== 'http' && setError(e)} // on 'http' the site's own error page shows
        onLoadStart={() => setError(null)}
        style={{ flex: 1 }}
      />
      {error ? (
        <View style={[StyleSheet.absoluteFill, { alignItems: 'center', justifyContent: 'center' }]}>
          <Text>Could not load the page</Text>
          <Button title="Retry" onPress={() => ref.current?.reload()} />
        </View>
      ) : loading ? (
        <ActivityIndicator style={StyleSheet.absoluteFill} />
      ) : null}
    </View>
  );
}

Scroll position¶

An injected script can report the main frame's scroll position over the bridge, at most once per frame. For the offsets during a bounce or a pinch too, use the onScroll extension.

import { useEffect, useMemo, useState } from 'react';
import { Text } from 'react-native';
import { WebView, createBridge, type InjectedScript } from 'react-native-minimal-webview';

const scrollScript: InjectedScript = {
  code: `{ // a block: an origins ['*'] script shares the page's global scope
  let queued = false;
  addEventListener('scroll', () => {
    if (queued) return;
    queued = true;
    requestAnimationFrame(() => { queued = false; window.nativeBridge?.emit('scroll', { x: scrollX, y: scrollY }); });
  }, { passive: true });
}`,
  origins: ['*'], // nativeBridge exists only on the bridge's allowedOrigins
};

export function Browser() {
  const bridge = useMemo(() => createBridge({ allowedOrigins: ['https://example.com'] }), []);
  const [scroll, setScroll] = useState({ x: 0, y: 0 });

  useEffect(() => bridge.on('scroll', (position) => setScroll(position as { x: number; y: number })), [bridge]);

  return (
    <>
      <Text>{scroll.y}</Text>
      <WebView
        source={{ uri: 'https://example.com' }}
        bridge={bridge}
        injectedScripts={[scrollScript]}
        style={{ flex: 1 }}
      />
    </>
  );
}
