    Interface ExtensionProps

    The react-native-webview props this package brings back, each by a native hook of its own.

    Setting a prop turns its hook on, and a change reaches the hook live, without recreating the WebView. A hook attaches only to a WebView that has set its prop, so a prop never set costs nothing. A prop marked for one platform does nothing on the other.

    Properties

    androidLayerType

    androidLayerType?: AndroidLayerType = 'none'

    The WebView's layer type, kept on the WebView that replaces one whose renderer crashed.

    basicAuthCredential

    basicAuthCredential?: BasicAuthCredential

    The credential the WebView answers HTTP auth challenges with, on every host.

    iOS answers HTTP basic challenges, and doesn't send a credential again once the site has rejected it; Android answers every HTTP auth request. A change applies from the next challenge. Without it, and for the challenges it doesn't answer, the core's handling applies: the challenge is declined and the site's 401 page shows.

    A credential once accepted stays with the WebView's network session, as in a browser: after the prop changes or is removed, an origin that accepted it can still get it, until the app restarts.

    hideKeyboardAccessoryView

    hideKeyboardAccessoryView?: boolean

    Hides the bar above the keyboard (previous, next, done) for the page's inputs.

    It changes a private WebKit view, as react-native-webview does, so a WebKit update can stop it working.

    menuItems

    menuItems?: readonly MenuItem[]

    Items that replace the system's in the text selection menu; onCustomMenuSelection gets the one chosen.

    Set it, or on iOS suppressMenuItems, when the WebView is created: a WebView created without either gets no menu from them until it is created again, and the core warns. Once it has, a change, removal included, applies to the next menu. Its hook makes the WebView from a class of its own, so when another hook's webViewClass or webViewFactory, registered earlier, makes it instead, there is no menu and the core warns. On iOS the items are added to WebKit's own selection menu.

    nestedScrollEnabled

    nestedScrollEnabled?: boolean

    Keeps a swipe that starts on the page for the page, inside a scrolling parent such as a ScrollView.

    android.webView.nestedScrollingEnabled doesn't do this: the parent still takes the swipe.

    onCustomMenuSelection

    onCustomMenuSelection?: (event: CustomMenuSelectionEvent) => void

    The menuItems item chosen, with the selected text.

    onDialog

    onDialog?: (dialog: Dialog, signal: AbortSignal) => unknown

    Answers the page's alert, confirm and prompt instead of the native dialogs; the page waits for the answer.

    The return value (a promise is awaited) is the answer: true accepts a confirm, a string is a prompt's text, and anything else, a throw too, dismisses the dialog (confirm false, prompt null). An alert's answer doesn't matter. There is no timeout: signal aborts when the page goes away first (a crash, an unmount), and the dialog is then dismissed. Without it, the core's dialogs show. Not a react-native-webview prop, whose dialogs are native.

    onScroll

    onScroll?: (event: ScrollEvent) => void

    Each change of the scroll offset, with no throttling.

    On iOS, the offsets include the content inset adjustment unless ios.scrollView.contentInsetAdjustmentBehavior is never, react-native-webview's default.

    suppressMenuItems

    suppressMenuItems?: readonly SuppressMenuItem[]

    The system items to hide from the text selection menu.

    Set it when the WebView is created, as menuItems.
