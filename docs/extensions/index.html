    @react-native-minimal-webview/extensions

    Native hooks for react-native-minimal-webview that bring back react-native-webview props, such as onScroll and basicAuthCredential, and add JS-answered dialogs.

    Setup

    It has the core's requirements. Install both, then rebuild the app, since the package has native code:

    npx expo install react-native-minimal-webview @react-native-minimal-webview/extensions

    Each extension is a function whose result goes into the core's extensions prop:

    import { basicAuthCredential, onScroll } from '@react-native-minimal-webview/extensions';
    import { WebView } from 'react-native-minimal-webview';

    export function Browser() {
      return (
        <WebView
          source={{ uri: 'https://example.com' }}
          style={{ flex: 1 }}
          extensions={[
            basicAuthCredential({ username: 'user', password: 'secret' }),
            onScroll(({ nativeEvent }) => console.log(nativeEvent.contentOffset.y)),
          ]}
        />
      );
    }

    Extensions

    Function Platforms
    basicAuthCredential(credential) iOS, Android
    dialogs(onDialog) iOS, Android
    menuItems({ items, suppress, onSelect }) iOS, Android (suppress: iOS)
    onScroll(handler) iOS, Android
    hideKeyboardAccessoryView() iOS
    nestedScrollEnabled() Android
    androidLayerType(type) Android

    Each function's API reference page has its behavior and limits. Its code is in the folder named after it: the TS, and the Swift or Kotlin for each platform it has.

    Vendoring an extension

    To change an extension, or to take only one, copy it into a module of your own:

    1. Create the module, with the core as its dependency and iOS 17.0 as its platform: steps 1 and 2 of Native hooks.
    2. Copy the extension's files into it:
      • the .swift file into ios/
      • the .kt file next to your module's <Name>Module.kt, in android/src/main/java/
      • index.ts, the function that returns its HookExtension, into src/ under the extension's name (such as src/basicAuthCredential.ts), and export it from your module's index.ts
    3. In the .kt file, change the package line to the one in your <Name>Module.kt.
    4. Register the hook in <Name>Module.swift and <Name>Module.kt, for each platform the extension has: call BasicAuthCredential.register(), with the extension's own name, inside the module's one OnCreate block (add one to definition() if it has none; on Android a second OnCreate replaces the first). The copies are in your module and its package, so they need no import.
    5. In the hook key, replace the @react-native-minimal-webview/extensions prefix with your package's name, in the Swift, the Kotlin and the TS.
    6. Rebuild the app.

    The Swift keeps its type names: they belong to your module.

    A changed hideKeyboardAccessoryView also needs a suffix of its own: the runtime class it makes is found by that name.

    With this package installed as well, a package line you forgot to change fails the Android build with a duplicate class. A key you forgot to rename fails at launch with "two hooks are registered under …: prefix yours with your package's name".
