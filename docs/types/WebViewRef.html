    Type Alias WebViewRef

    A WebView's ref.

    A handle kept after its WebView unmounted is safe to call: the navigation methods do nothing, and evaluate, get, call and hook reject with unavailable, and one still pending when the WebView unmounts rejects with navigated.

    Those four wait up to about a second for a WebView that has just mounted (on Android, a call from the parent's first effect can come before the view exists), then reject with unavailable; in the background they don't wait.

    call

    • call(method: string, args?: unknown[]): Promise<unknown>

      Calls a platform method, root.method, and resolves with its result through JSON.

      Android: a public method of settings (then WebSettingsCompat's statics), webView (then WebViewCompat's), cookieManager or webStorage.

      iOS: an Objective-C selector on a root of IOSSettings, websiteDataStore or httpCookieStore.

      Rejects with native_error for an unknown method, a wrong argument count, an argument that doesn't fit, a method that raises, a result JSON can't carry (iOS: NaN), and what the core owns: on iOS every selector that loads, navigates (setInteractionState: too), runs a script, starts a download or sets a delegate, and private (_), KVC, KVO, performSelector, init…, copy…, mutable…, new… and reference-counting selectors; on Android (in get too) the loads, navigations, clients, JavaScript interfaces, web message listeners, document-start scripts, destroy, removeAllViews, pauseTimers, resumeTimers and evaluateJavascript.

      A trailing completion handler (iOS) or ValueCallback (Android) is left out of args: the call resolves with what it reports, or on iOS rejects with its error. On iOS, a selector whose completion handler isn't in this package's SDK headers, or reports something other than an object, an error or an integer, rejects with native_error. On Android, a method that takes args as they are wins over one that also takes a callback, and a null in the callback's place passes none.

      On iOS one mistake the signature can't catch crashes the app: an object argument of the wrong class; for a method that takes another object, write a native hook.

      Parameters

      • method: string
      • args: unknown[]

        The method's arguments. On iOS they are converted by its signature: booleans, numbers, strings, the structs as objects, null for nil, and { set: [...] }, { date: seconds }, { data: base64 } or { cookie: properties } for an NSSet, NSDate, NSData or NSHTTPCookie. A cookie's properties are NSHTTPCookie's keys: Name, Value, Domain and Path are required; Max-Age (seconds, as a string), Secure, HttpOnly and SameSite are some of the optional ones. A tag that can't make its object ({ data } that isn't base64, a { cookie } without a required key) rejects with native_error.

      Returns Promise<unknown>

      On iOS: numbers, strings, an NSURL as a string, an NSDate as seconds, NSData as base64, a UIImage as a base64 PNG, the structs as objects, an NSHTTPCookie as its properties (Expires in seconds), and arrays, sets and dictionaries of them. On Android: primitives, strings, and lists and maps of them. Any other object is null.

      Example

      await ref.current?.call('webView.clearCache', [true]); // Android
      await ref.current?.call('scrollView.setContentOffset:animated:', [{ x: 0, y: 100 }, true]); // iOS

    evaluate

    • evaluate(script: string): Promise<unknown>

      Runs an expression (not statements) in the page's main frame and awaits it.

      Resolves with its value through JSON: null for what JSON can't encode (a function, NaN, a cycle), a Date as its ISO string. The value is the page's, so treat it as page data. Rejects with a CodedError: script_error (with the script's error message), navigated or unavailable. There is no timeout: a page can hold a call until it navigates.

      Parameters

      • script: string

    get

    • get(key: string): Promise<unknown>

      A platform setting read by name, through JSON as call converts results.

      The roots are those of IOSSettings and AndroidSettings, plus websiteDataStore and httpCookieStore on iOS and cookieManager and webStorage on Android. On Android, textZoom reads getTextZoom(), isTextZoom() or a non-void textZoom(). Rejects with a CodedError: not_found for an unknown root or key, unavailable for one this WebView doesn't support (Android), and native_error for one it can't read or that the core owns.

      Parameters

      • key: string

      Example

      const bounces = await ref.current?.get('scrollView.bounces'); // iOS
      const textZoom = await ref.current?.get('settings.textZoom'); // Android

    goBack

    • goBack(): void

      Goes back one page, when canGoBack.

      On Android, as Chrome's back button, it also skips the history entries a page added without a user gesture (pushState, a hash change) and the page that added them.

    goForward

    • goForward(): void

      Goes forward one page, when canGoForward.

    hook

    • hook(name: string, method: string, args?: unknown[]): Promise<unknown>

      Calls the method handler the native hook name registered with context.handle, with args, and resolves with its reply; both cross as JSON.

      The reply converts as call's results do: an object JSON can't carry is null, and NaN rejects with native_error. Rejects with a CodedError: not_found when no attached hook name handles method. A navigation or a crash doesn't settle a call whose handler hasn't replied; only an unmount does.

      Parameters

      • name: string
      • method: string
      • args: unknown[]

    reload

    • reload(): void

      Reloads the page; after a failed load, retries the failed URL.

      Sends a POST source again, and resets the crash guard that stops crash.

    stopLoading

    • stopLoading(): void

      Stops the load: its outcome is cancelled, or on Android finished once the page has arrived.
