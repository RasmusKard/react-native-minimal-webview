    Type Alias AndroidSettings

    Android settings by setter name without set, applied by reflection, so any public setter works, including ones a newer SDK or androidx.webkit adds (under a root's other).

    The keys the SDK lists autocomplete, with their @since; the constants are in AndroidConstants.

    A key with no public setter for the value's type, or one this device's WebView lacks, is skipped with a warning; nothing here can crash the app. A root's default keys are the package's, and yours go over them. Read one back with the ref's get.

    Example

    <WebView
      source={{ uri: 'https://example.com' }}
      android={{
        settings: { textZoom: 120, cacheMode: AndroidConstants.WebSettings.LOAD_NO_CACHE },
        webView: { overScrollMode: 2 },
      }}
    />

    Properties

    settings

    settings?: SettingsRoot<AndroidSettingKeys["settings"]> = { userAgentString: null }

    WebSettings setters, then static WebSettingsCompat ones.

    Each new WebView starts with javaScriptEnabled, domStorageEnabled, supportMultipleWindows and builtInZoomControls on; allowFileAccess, allowContentAccess, displayZoomControls and downloadFaviconsEnabled off; mixedContentMode MIXED_CONTENT_NEVER_ALLOW; and, with WebView 146 and newer, backForwardCacheEnabled on. userAgentString: null is WebView's default user agent.

    webView

    webView?: SettingsRoot<AndroidSettingKeys["webView"]> = { webContentsDebuggingEnabled: __DEV__ }

    WebView setters (static and inherited View ones too), then WebViewCompat ones, then CookieManager's acceptThirdPartyCookies.

    webContentsDebuggingEnabled is process-wide.
