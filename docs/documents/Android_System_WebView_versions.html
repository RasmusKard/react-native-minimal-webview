    Android System WebView versions

    Some features need a newer Android System WebView than the minimum Android version brings. This page says why the version matters, how to check and update a device's, and how to test the old ones. Each item's API reference gives the version it needs.

    Android System WebView updates apart from Android, so a device's API level doesn't tell you its WebView.

    The core checks each feature at run time. On an older WebView the feature is off, and nothing crashes.

    What needs a newer WebView

    • evaluate
    • blob: downloads with onDownload
    • The bridge
    • injectedScripts
    • pendingUrl
    • onLoadStart and onLoadEnd for a load that never commits
    • SSL errors on back and forward loads in onError
    • backForwardCacheEnabled on by default

    A WebSettingsCompat or WebViewCompat key, a compat method through get or call, and WebView.android.preconnect depend on an androidx.webkit feature instead of a WebView version. The keys' and preconnect's TSDoc name it.

    Check a device's WebView

    The version is the Chrome version in the WebView's user agent: read WebView.android.defaultUserAgent and look for Chrome/<version>.

    On a connected device, adb shell dumpsys webviewupdate names the WebView package in use and its version.

    Update a device's WebView

    Update Android System WebView in the Play Store. On an emulator, use a Google APIs system image: a Play Store image updates WebView in the background, so its version moves under your tests.

    Test the oldest versions

    An emulator with a Google APIs image keeps the WebView its image shipped with, and the images of older API levels ship older WebViews. Run the app there to see the features above off. CONTRIBUTING lists the images for the oldest supported versions and how to create the emulators.
