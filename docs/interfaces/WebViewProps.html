    Interface WebViewProps

    The WebView's props.

    The ones from React Native's ViewProps (style, testID, nativeID, the accessibility props, layout and touch events) go to the native view.

    JS dialogs (alert, confirm, prompt) and HTTP auth have no prop: iOS shows a UIAlertController titled with the frame's host, one at a time, and Android WebView's own dialogs; an auth challenge is declined, so the site's 401 page shows. A native hook takes them over (HookDialogs and HookAuth in example/modules/sample-extension).

    Properties

    android

    android?: AndroidSettings

    Android settings by setter name; see AndroidSettings.

    A key you remove keeps its value until the WebView is recreated, unless the package sets it (webContentsDebuggingEnabled, userAgentString): that one goes back to the package's default. The userAgent prop wins over the same key here.

    bridge

    bridge?: Bridge<BridgeMethodMap, BridgeEventMap>

    The bridge to the page, from createBridge.

    Read when the WebView is created: another bridge recreates it (the page reloads and the navigation state starts over), so make it once (useMemo). A bridge serves one mounted WebView at a time: attaching it to a second throws.

    hookOptions

    hookOptions?: Record<string, unknown>

    Each native hook's value by its key.

    A key whose value is not null, undefined or false attaches its hook, and a later change reaches that hook live, without recreating the WebView; removing the key passes the hook null, and it stays attached. A key turned on after the WebView was created attaches its hook then, unless the hook has a configure step: that one attaches only when the WebView is created, and a warning says so. A key no hook is registered under warns: pass a one-platform hook's key on that platform only.

    See

    Native hooks example

    injectedScripts

    injectedScripts?: InjectedScript[]

    Scripts to run at document start, before the page's own, on every page and origin the WebView visits (and with allFrames: true in cross-origin iframes): guard with location.origin.

    A change applies from the next navigation. On Android with a WebView older than 101 they don't run (a warning says so, once per process).

    ios

    ios?: IOSSettings

    WebKit settings by property name; see IOSSettings.

    A key you remove keeps its value until the WebView is recreated, unless the package sets it (inspectable, customUserAgent): that one goes back to the package's default. The userAgent prop wins over the same key here.

    navigationRules

    navigationRules?: NavigationRule[]

    Which navigations load in place, open externally or are blocked, decided natively; the first matching rule wins, and with no match the navigation is blocked.

    With no rules (or []), http(s) loads in place, file: is blocked, and other schemes open externally from the main frame, with or without a user gesture (rules can require one with userInitiated: true), and are blocked from a subframe. about:, blob:, data: and javascript: always load in place.

    The source load, reloads and back/forward skip the rules; a redirect of the source load doesn't, nor on Android a redirect of a reload or back/forward. The rules never see a form POST, on either platform: it loads in place, and one to a new window loads in place on iOS and doesn't load on Android.

    An external intent: URL (Android) opens only as a browsable intent, without its explicit component or selector; when no app handles it, its S.browser_fallback_url goes through the rules and the intent: itself is reported as block.

    See

    Navigation rules example

    onDownload

    onDownload?: (result: Download | DownloadFailure) => void

    A download finished (Download) or failed (DownloadFailure).

    With this prop the core saves the file: iOS downloads it in the page's session; Android fetches it again with the host's cookies (whatever their SameSite) and the page's user agent. That fetch sends no POST body, source headers or HTTP auth, so such a download can fail or save a login page, and it fails above 100 MB, on a redirect off https, and for blob: on a WebView older than 83.

    Without this prop, an http(s) download opens externally (onOpenExternal or the system browser, without the page's session), and a data: or blob: one is dropped. A PDF is a download on Android; iOS shows it inline.

    onError

    onError?: (event: LoadErrorEvent) => void

    A main-frame load failed, or got an HTTP error status.

    After a failed load iOS keeps the page before it on screen, and Android shows WebView's own error page. On Android with a WebView older than 146, an SSL error on a back/forward load isn't reported.

    onFileRequest

    onFileRequest?: (
        request: FileRequest,
        signal: AbortSignal,
    ) => string[] | Promise<string[] | null> | null

    Answers <input type="file"> with file:// or content:// URIs, or null to cancel.

    Without it, the system file chooser opens, one at a time for the whole app, and ignores capture: a request while one is open is cancelled, and after a chooser that never returns a result, so is every request until the app restarts.

    iOS always shows WebKit's picker, which needs NSCameraUsageDescription and NSPhotoLibraryUsageDescription.

    signal aborts when native stops waiting (the page moved on, crashed or unmounted), and a late answer is dropped; until it settles, the page's next file request waits.

    onFullscreenChange

    onFullscreenChange?: (event: FullscreenChangeEvent) => void

    The page entered or left fullscreen (active).

    Fullscreen works without it: the page's view covers the window, the system bars hide and back exits. iOS shows WebKit's own fullscreen, not reported.

    onHookEvent

    onHookEvent?: (event: HookEvent, signal?: AbortSignal) => unknown

    An event from a native hook.

    For an ask, the return value (a promise is awaited) is the answer; undefined or a throw answers null. signal is set only for an ask, and aborts when native stops waiting for the answer: an ask has no timeout, but one still open when the page goes away is answered null.

    onLoadEnd

    onLoadEnd?: (state: NavigationState) => void

    loading went false: state.outcome says how the load ended.

    onLoadStart

    onLoadStart?: (state: NavigationState) => void

    loading went true.

    On Android with a WebView older than 146, a load that never commits fires neither this nor onLoadEnd.

    onNavigation

    onNavigation?: (event: NavigationEvent) => void

    Every navigation the rules, or their defaults, decided.

    Not reported: the source load, reloads, back/forward, and a navigation a native hook decides.

    onNavigationRequest

    onNavigationRequest?: (
        request: NavigationRequest,
        signal: AbortSignal,
    ) => NavigationAction | Promise<NavigationAction>

    Answers ask rules within 1 s.

    A late, missing or other answer is block, as is one still pending when another page commits, and signal then aborts. Without this prop, ask is block. Until the next commit, a URL it allowed isn't asked again on a redirect back to it (Android), or when the same kind of frame loads it again (iOS).

    onNavigationStateChange

    onNavigationStateChange?: (state: NavigationState) => void

    Every change to the navigation state. Changes within one frame are combined into one call.

    onOpenExternal

    onOpenExternal?: (url: string) => boolean | void | Promise<boolean | void>

    Opens external navigations, every one, an Android intent: URL included, before onNavigation reports them.

    Return false (a promise is awaited) to hand one back: the core then opens it as it does without this prop, an intent:'s fallback URL included. Anything else, a throw too, means you opened it. Default: the system browser or app for the URL, opened without asking canOpenURL first, so no LSApplicationQueriesSchemes (iOS) or <queries> (Android) entries are needed.

    onPermissionRequest

    onPermissionRequest?: (
        request: PermissionRequest,
        signal: AbortSignal,
    ) => boolean | Promise<boolean>

    Camera, microphone and, on Android, location and protected media (DRM) for the main frame.

    Answer true to grant, having asked the OS first (expo-camera, expo-location): without OS permission the page's request fails anyway. On iOS, true also skips WebKit's own prompt.

    Without this prop, Android denies and iOS shows WebKit's prompt (location always does). Android keeps a location answer until the page changes.

    signal aborts when native stops waiting (the page moved on, crashed or unmounted, or Android withdrew the request), and a late answer is dropped; until it settles, the page's next request of the same kind waits.

    onProcessGone

    onProcessGone?: (event: ProcessGoneEvent) => void

    The renderer died; see ProcessGoneEvent for the recovery.

    Android's WebViews share one renderer, so each of them reports its death.

    pullToRefresh

    pullToRefresh?: boolean

    Pull down at the top of the page to reload: UIRefreshControl on iOS, SwipeRefreshLayout on Android, where a pull inside a scrolled inner scroller (overflow: auto) scrolls it instead.

    ref

    ref?: Ref<WebViewRef>

    Gets the WebViewRef.

    Give each mounted WebView its own ref: with two, the last mounted wins (with a warning in development) until it unmounts.

    sharedCookies

    sharedCookies?: boolean

    Copies HTTPCookieStorage (native requests) into the WebView before each source load, which waits for it, and the WebView's cookie changes, deletions included, back as they happen.

    Android needs nothing: CookieManager is shared app-wide, and flushed when the app goes to the background.

    source

    source: WebViewSource

    What to load.

    A new source loads at once, unless it equals the loaded one field by field: that loads nothing, even after the page navigated away.

    userAgent

    userAgent?: string

    Replaces the whole user agent (ios.webView.customUserAgent, android.settings.userAgentString).

    To append to the default one instead, set ios.configuration.applicationNameForUserAgent and, on Android, android.settings.userAgentString to WebView.defaultUserAgent plus your suffix.
